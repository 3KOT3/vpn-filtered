# Проверка из России на своём сервере

Подходит для **Cloud.ru Evolution free tier** (2 vCPU, 4 ГБ RAM, 30 ГБ — бесплатно
навсегда) и любого другого VPS в России (Timeweb, aeos, reg.ru, Selectel).

Что получается: сервер сам раз в 2 часа проверяет конфиги **из российского
дата-центра** (YouTube → Telegram → дата-центр Telegram → скорость) и публикует
список боту. Компьютер после этого не нужен.

## 1. Регистрация в Cloud.ru (3 минуты)

1. Откройте <https://cloud.ru/> → **Зарегистрироваться**.
2. Подтвердите телефон (SMS) и почту — это делаете вы, данные аккаунта личные.
3. В консоли: **Evolution → Compute → Виртуальные машины → Создать**.
   - Образ: **Ubuntu 24.04**;
   - конфигурация: **2 vCPU / 4 ГБ / 30 ГБ** (это и есть free tier);
   - сеть: публичный IP (достаточно).
4. Возьмите **IP** и пароль root — они понадобятся для входа по SSH.

> Бесплатный уровень Cloud.ru — это **постоянно бесплатная ВМ** в указанной
> конфигурации, в отличие от пробных периодов. Платить не нужно, пока не
> увеличиваете конфигурацию.

## 2. Установка одной командой

Подключитесь к серверу:

```bash
ssh root@ВАШ_IP
```

И запустите:

```bash
apt-get update -qq && apt-get install -y git
git clone --depth 1 https://github.com/3KOT3/vpn-filtered.git
cd vpn-filtered
sudo CHECKER_KEY='СЕКРЕТ_СПРОСИТЕ_У_ВЛАДЕЛЬЦА_БОТА' bash deploy/vm/install.sh
```

Всё: скрипт поставит Python и sing-box, разложит проект в `/opt/vpn-checker`,
включит таймер systemd и сразу сделает первый прогон (2–3 минуты).

## 3. Проверить, что работает

```bash
systemctl list-timers vpn-checker.timer     # когда следующий запуск
journalctl -u vpn-checker.service -f        # логи прогона
```

В конце лога будет примерно:

```
публикую 12 конфигов
  список -> HTTP 200 {"ok": true, "kept": 12, "quiet": true}
  статус -> HTTP 200 {"ok": true, ...}
```

И в боте сразу обновятся `/sub.txt` и `/sub-hiddify.json`.

## Настройки

Задаются при установке (или правкой `/etc/systemd/system/vpn-checker.service`):

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `CHECKER_KEY` | — (обязательно) | секрет публикации списка |
| `PUBLISH_KEY` | `pub-7Qm2xVp9LzR4tNb8sWk3` | ключ публикации статуса |
| `WORKER_URL` | адрес воркера бота | куда публиковать |
| `MIN_MBPS` | `1.0` | порог скорости |
| `SOURCES` | `6,22,23` | какие файлы проверять |
| `INTERVAL_HOURS` | `2` | как часто проверять |

После правки сервиса: `systemctl daemon-reload && systemctl restart vpn-checker.timer`.

## Частые вопросы

**Нужен ли белый IP?** Сервер сам ходит наружу, входящие соединения не нужны —
достаточно любого публичного адреса.

**Что если прогон упал?** `publish.py` не публикует пустой список — у бота
остаётся предыдущий рабочий. Причина видна в `journalctl`.

**Можно ли совместить с домашней проверкой?** Да: серверная публикует в тот же
KV, бот берёт самый свежий список. Когда ПК включён — можно оставить и его.
